# OMC-CSP outer-inner opportunity v1

## Question

Does the frozen multi-GPU OMC-CSP workflow leave enough recoverable work to
justify dynamic communication between the outer task scheduler and inner BFGS
scheduler?

This experiment observes the accepted workflow without changing its numerical
or scheduling decisions. Host-relative timestamps are recorded for task
dispatch, completion, and active-compaction events. Empty resident slot-time is
then separated into:

- `refill_opportunity`: all GPUs are busy and a compatible undispatched system
  exists;
- `incompatible_pending`: work remains, but not for the released optimizer
  shape;
- `idle_gpu_with_ready_work`: an outer-dispatch defect;
- `materialization_or_dispatch_wait`: a GPU is idle before its next input is
  ready;
- `unavoidable_tail`: every system has already been dispatched.

The compatibility key for variable-cell full BFGS is exact
`(atom_count, 3 * atom_count + 9)`. Candidate-edge count is not a correctness
key because incoming candidate graphs are rebuilt.

## Results

Each row is one deterministic H100 run. OBEQIX is a homogeneous 2,048-CIF
held-out pool; MIX is the held-out 512-CIF inter-family workload. Percentages in
the four opportunity columns are fractions of resident slot-time. Materialize
and idle-tail percentages are fractions of available production GPU-time.

OBEQIX execution scaling is 1.776x from G2 to G4 and 2.440x from G2 to G8.
The dispatcher itself is not the bottleneck: ready-work idle GPU-time is at
most 0.02%. Increasing GPU count instead exposes cold materialization and final
queue exhaustion. At G8, 17.62% of production GPU capacity is idle after every
structure has already been assigned.

The homogeneous pool contains a real inner-scheduler opportunity: about
21-26% of resident slot-time is both empty and compatible with undispatched
work. Perfect recovery would raise slot utilization by at most about 1.30x at
G4/G8 and 1.36x at G2. These are occupancy ceilings, not wall-time speedup
predictions; refill mutation, graph construction, synchronization, and changed
batch efficiency consume part of the bound.

The mixed control establishes the boundary. Its 48.58% empty slot-time is not
one refill target: only 12.47% is compatible, while 15.84% has only incompatible
pending work and 20.14% is an exhausted-queue tail. Cross-shape refill would
require a resident repack and would invalidate the state-preserving fixed-slot
mechanism.

## Decision

Do not add an initial/middle/tail state machine or a per-structure duration
predictor. Retain deterministic cost-balanced complete chunks and active drain
as the multi-GPU default.

The outer scheduler may form a refill-enabled queue only when all of these are
true:

- the queue has one exact optimizer-shape compatibility key;
- more than one resident wave remains after initial dispatch;
- the optimizer supports state-preserving fixed-slot replacement;
- packaged evidence accepts refill for that optimizer and workload class.

The first implementation should not add a live cross-GPU control channel. The
outer scheduler should preconstruct one compatible pending micro-pool per GPU.
Each inner scheduler can then fill released slots from its local prefetched
queue at existing convergence boundaries and drain after that queue is
exhausted. No live optimizer state is migrated between GPUs.

The bounded local-cohort experiment is complete in
`omc-csp-multigpu-local-refill-v1`. It regressed G2/G4 by 3.6%/3.2%, accelerated
G8 by 11.7%, and failed the strict G8 endpoint gate for one structure. Private
refill therefore remains explicit-only. The next candidate is bounded
source-backed streaming refill, which must retain the useful G8 reduction in
draining model calls without coarse initial materialization or static queue
ownership. Mixed inter-family refill remains disabled.

Machine-readable classifications are generated by
`benchmarks/analyze_outer_inner_opportunity.py`. Raw run JSON and logs remain on
the H100 experiment host.
